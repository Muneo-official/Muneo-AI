# 파싱 프롬프트 카테고리 개선 — 결과

## 배경

`pipeline/validators.py`로 `estimate_cases`를 소급 검증하면서 `unknown_category` 위반의
실제 내용을 까봤다(`pipeline/results/validation_report.md`). 가장 많이 등장한 두 카테고리:

- **"기타공사"(3,118건)**: 승강기 보양비, 주민동의서 대행료, 폐기물 처리비, 하자보수 보증증권
  발행 수수료 등 — 정체불명의 잡항목이 아니라 **거의 모든 리모델링 견적서에 공통으로 등장하는
  부대비용**이었다. 표준 카테고리가 없었을 뿐.
- **"단가참고"(557~848건)**: 실크벽지, 양변기, 인조대리석 상판 같은 완전히 정상적인 개별
  작업 항목이었다. 원본 이미지의 표/섹션 제목("단가참고")을 그대로 category로 복사한 것으로
  추정됨.

`CATEGORY_NORM`(매핑 테이블)을 아무리 늘려도 못 고치는 문제다 — "단가참고" 안에는 도배·욕실·
전기·가구가 다 섞여 있어 통째로 한 카테고리에 매핑하면 또 오분류가 난다. 근본 원인이 파싱
프롬프트에 있다고 보고 프롬프트 자체를 개정했다.

## 수정

`pipeline/prompts.py`(신규, `pipeline/reference/parse_estimates.py`의 PARSE_PROMPT을 원본으로):

1. **규칙 7에 "기타/공과잡비" 표준 카테고리 추가** — 승강기 보양, 주민동의서, 폐기물처리,
   준공청소, 하자보수, 보증증권 발행, 안전관리, 소방
2. **규칙 7-1 신설** — "단가참고", "단가표", "옵션참고" 같은 표/섹션 제목을 그대로 category로
   쓰지 말고, 그 안의 개별 품목을 실제 작업 내용으로 분류하라고 명시

`pipeline/categories.py`의 `CATEGORY_NORM`에도 대응 매핑 추가: `"기타/공과잡비"` → `"공과잡비"`,
`"확장공사"` → `"확장"` (기존 12개 공종 어디에도 안 맞아 별도 버킷).

## 실제 검증 — Vision API 실호출 (10회)

`ANTHROPIC_API_KEY`와 실제 크롤링 이미지(`종합프로젝트/estimate/estimate_data/`)로 OLD/NEW
프롬프트를 같은 이미지에 실제로 호출해 비교했다.

**1차 시도 (실패)**: 이미지 청크 분할 없이 통째로 보냈더니 카테고리명이 호출마다 흔들림
("건기공사", "샷호공사" 같은 오타성 출력). 원본 설계(`SPLIT_HEIGHT_THRESHOLD=3000`,
`CHUNK_HEIGHT=2000`)를 안 지킨 방법론 오류였음 — 731×3050px 이미지를 그대로 보냈다.

**2차 시도 (청크 분할 적용)**: 원본 설계대로 3000px 초과 이미지를 2000px 청크(200px 겹침)로
나눠 각각 호출 후 병합. 결과: OLD/NEW가 거의 완전히 일치(한 사례는 카테고리 분포 100% 동일,
다른 사례는 오타 변형 하나만 차이) — **회귀는 없음을 확인.**

**한계**: 테스트한 이미지에서 "단가참고" 패턴 자체가 재현되지 않았다. LLM 응답은 완전히
결정론적이지 않아서, DB에 저장된 실제 파싱 당시엔 그 오류가 났더라도 재호출 시 우연히 안
날 수 있다 — 이 특정 버그는 확률적 오류로 보이며, 몇 번의 재호출로 강제 재현을 시도하는 건
비용 대비 수확체감이 크다고 판단해 중단했다.

## 부수 발견 — 크롤링 필터링 문제 실증

테스트 중 `850258_0.jpg`(공사 현장 사진), `850258_2.png`(회사 로고)가 파싱 대상 폴더에
섞여 있는 것을 확인했다 — 파싱 프롬프트의 `is_estimate: false` 판단으로 결과에는 안
들어가지만, **크롤링 단계에서 걸러지지 않고 Vision API 호출까지 도달한다**(토큰 낭비).
이 에픽의 4단계(크롤링 사전 필터링)가 다뤄야 할 문제의 실제 사례.

## 결론

- 프롬프트 개정 자체는 실제 DB 데이터(3,118건 + 557~848건)에 근거한 합리적 수정
- 회귀(기존 정상 케이스를 망가뜨림) 없음을 실제 API 호출로 확인
- 목표했던 특정 버그("단가참고" 재분류)의 직접 재현·검증은 실패 — 확률적 오류라는 특성상
  이번 세션에서는 여기서 멈추고, 다음 크롤링 배치에서 실제 발생 빈도가 줄어드는지 지켜보는
  것으로 결론
- 카테고리 출력의 근본적 안정성 문제(같은 이미지에 다른 카테고리가 나오는 것)는 프롬프트
  지시만으로는 한계가 있음 — 다음 단계(구조화 출력/tool use로 category enum 강제)가 이
  문제의 더 근본적인 해법으로 판단됨

## 재현 방법

프롬프트 자체는 API 호출 없이 바로 확인 가능:
```bash
python -c "from pipeline.prompts import PARSE_PROMPT; print(PARSE_PROMPT)"
```

실제 비교 테스트는 `ANTHROPIC_API_KEY`와 로컬 크롤링 이미지가 필요하며, 비용이 발생하는
작업이라 이 저장소에는 재현 스크립트를 커밋하지 않았다(스크래치 전용으로 실행).
