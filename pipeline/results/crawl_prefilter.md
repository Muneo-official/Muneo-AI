# 크롤링 사전 필터 — 결과

## 배경

`pipeline/results/prompt_category_fix.md`에서 실제로 확인했듯, 견적서가 아닌 이미지
(현장사진, 로고)가 크롤링 필터를 거치지 않고 Vision API 호출까지 도달하고 있었다.
파싱 프롬프트의 `is_estimate: false` 판단이 안전망 역할을 하지만, 그건 **API를 이미
호출한 뒤**에야 걸러내는 것이라 토큰 비용은 이미 쓴 뒤다. 이번 단계는 그 이전에
저비용으로 걸러내는 필터를 만든다.

## 조사 — 실제 데이터로 얼마나 심각한지 정량화

실제 크롤링 이미지 전체(`estimate_data/`, 1,626개)를 SHA-256 해시로 분석:

| | 값 |
|---|---:|
| 전체 이미지 | 1,626개 |
| 고유 해시 | 978개 |
| 3회 이상 반복되는 해시 | 14개 |
| 그 14개가 차지하는 전체 파일 수 | **656개 (40.3%)** |

**전체 크롤링 이미지의 40.3%가 단 14개의 바이트 단위로 동일한 파일**이었다. 반복 횟수
상위 2개(1600×2133 71회, 1600×1067 60회)를 실제로 열어서 확인한 결과, 각각 **견적과
무관한 카페 사진**과 **완성 견본 인테리어 사진**이었다 — 로고·뱃지·회사 프로필사진·
포트폴리오 사진이 매 게시글마다 똑같이 첨부되고 있었다.

## 설계 — 크기/비율 휴리스틱 대신 해시 블록리스트

크기·비율 기반 휴리스틱(정사각형이면 로고, 세로로 길면 표 등)도 검토했으나, 애매한
경계 케이스에서 진짜 견적서 표를 잘못 거를 위험(false negative)이 있다. 대신
**"다른 게시글과 바이트 단위로 완전히 동일한 파일"**이라는 조건을 썼다 — 실제 견적서
내용은 게시글마다 다를 수밖에 없으므로 이 조건은 오탐 위험이 사실상 없다.

## 구현

- `pipeline/crawl_filter.py`
  - `KNOWN_BOILERPLATE_HASHES`: 실측으로 확인된 14개 해시 (고정 블록리스트)
  - `compute_image_hash(path)`, `is_boilerplate(path, hashes)`: 조회 함수
  - `find_boilerplate_hashes(image_paths, min_occurrences)`: 새 크롤링 배치가 쌓이면
    같은 방법으로 블록리스트를 갱신할 때 쓰는 함수
- `pipeline/vision_client.py`의 `parse_image()`: 호출 시작 지점에서 `is_boilerplate()`
  체크 — 보일러플레이트면 API 호출 없이 즉시 `{"is_estimate": False}` 반환
- `pipeline/batch_client.py`의 `build_batch_requests()`: 보일러플레이트 이미지는 아예
  배치 요청 목록에 안 넣음(tool use 응답을 받고서 거르는 것보다 요청 자체를 줄이는 게
  실제 비용 절감)

## 실제 검증

`vision_client.parse_image()`를 알려진 보일러플레이트 실제 파일(882475_0.jpg, 카페
사진)로 호출 — API 호출 없이 **0.000초**만에 `{"is_estimate": False}` 반환 확인.

## 결론

- 필터를 적용하면 다음 크롤링 배치부터 API 호출량이 최소 40% 이상 줄어들 것으로 기대
  (이번 조사 표본 기준 — 새 배치의 정확한 비율은 다를 수 있음)
- 해시 기반이라 오탐(진짜 견적서를 잘못 거름) 위험이 구조적으로 낮음 — 실측으로 확인한
  14개 전부 실제로 무관한 이미지임을 육안으로도 확인

## 한계

- `KNOWN_BOILERPLATE_HASHES`는 **현재 시점의 스냅샷**이다 — 크롤링 소스(박목수 카페
  템플릿, 광고 배너 등)가 바뀌면 새로운 보일러플레이트가 생길 수 있고, 그건 이 고정
  목록으로 못 잡는다. `find_boilerplate_hashes()`로 주기적으로 재스캔해서 갱신하는
  운영 절차가 필요하다(자동화는 이번 범위 밖)
- 3회 미만 반복되는 보일러플레이트(우연히 1~2개 게시글에만 잘못 첨부된 무관한 사진 등)는
  이 방식으로 못 잡는다 — 다만 그런 건 애초에 비용 영향이 작다
